# 手牌系统设计文档

## 1. 系统目标

手牌系统负责展示当前关卡可用的防御塔，向玩家提供防御塔费用、职业图标和角色头像，并把“部署”和“升级”两种操作转发给 `ATDPlayerController`。手牌的塔类来源于关卡 GameMode 的 `LevelHandCards` 数组，手牌等级保存在 PlayerController 中。

## 2. 主要类与数据

| 类/字段 | 作用 |
|---|---|
| `ATDGameMode::LevelHandCards` | 当前关卡的防御塔类列表，数组索引是手牌逻辑索引 |
| `ATDPlayerController::HandCardLevels` | 每个手牌位的当前等级，默认全为 1，等级上限为 3 |
| `UTDHandPanel` | 创建、排列和整体刷新手牌 Widget |
| `UTDHandCard` | 单张手牌 Widget，显示图标、头像、费用并响应按下/松开 |
| `FTowerLevelStats` | 塔各等级的生命、伤害、间隔、费用和防御属性 |
| `WBP_HandPanel` | 手牌容器蓝图，绑定 `RootCanvas` 和 `HandCardClass` |
| `WBP_HandCard` | 单卡蓝图，绑定图片、费用文本和升级动画 |

## 3. 手牌创建流程

`ATDGameMode::BeginPlay` 创建 `HandPanelClass` 对应的 `UTDHandPanel`，并将其添加到 Viewport。`UTDHandPanel::NativeConstruct` 执行以下步骤：

1. 检查 `RootCanvas`、`HandCardClass` 和拥有者 PlayerController；
2. 调用 `GetDescendingSortedHandCardIndices` 获取按初始部署费用降序排列的手牌索引；
3. 为每个索引创建 `UTDHandCard`；
4. 从 PlayerController 读取费用，并从塔类默认对象读取 `TowerClass`；
5. 根据职业枚举加载 `/Game/Resource/ico/` 下的职业图标；
6. 根据塔类名称加载 `/Game/Resource/Avatar/` 下的角色头像；
7. 调用 `Card->Initialize()` 完成蓝图初始化；
8. 将卡片添加到 RootCanvas 右下角，并按卡片尺寸和间隔横向排列。

## 4. 费用读取规则

`ATDPlayerController::GetHandCardCost` 根据手牌等级从塔类默认对象的 `LevelStats` 中读取费用：

- 等级 1 读取 `LevelStats[0]`；
- 等级 2 读取 `LevelStats[1]`；
- 等级 3 读取 `LevelStats[2]`；
- 如果对应等级不存在，则回退到 `LevelStats[0]`，再回退到塔的 `CostToDeploy`。

这使每张手牌的显示费用与实际 `DeployAtCell` 使用的部署费用保持一致。

## 5. 排序规则

PlayerController 提供两种排序函数：

- `GetSortedHandCardIndices`：按等级 1 的部署费用升序；
- `GetDescendingSortedHandCardIndices`：按等级 1 的部署费用降序。

当前 `UTDHandPanel` 使用降序结果创建卡片，因此费用较高的卡位于更靠前的位置。排序只影响显示顺序，卡片内部保存的 `CardIndex` 仍然是 `LevelHandCards` 的原始数组索引，点击后不会因显示排序而取错塔类。

## 6. 单卡 Widget 行为

`UTDHandCard::NativeConstruct` 完成图片、头像和费用文本初始化，并查找蓝图中的第一个 `UButton`，重新绑定按下和松开事件。`UpdateCost` 把浮点费用转换为整数文本显示。

### 6.1 普通模式

按下卡片调用 `ATDPlayerController::BeginPlacement(CardIndex)`，开始创建 GhostActor 和部署预览；松开卡片调用 `EndPlacement()`，进入部署倒计时。若玩家在拖拽过程中点击其他位置，PlayerController 的 `OnClick` 会取消当前部署。

### 6.2 升级模式

HUD 的升级按钮调用 `EnterUpgradeMode`。在升级模式下，按下卡片不会开始部署，而是调用 `TryUpgradeHandCard(CardIndex)`：

1. 检查索引有效、当前等级小于 3；
2. 根据当前等级读取 `UpgradeCost_Lv2` 或 `UpgradeCost_Lv3`；
3. 调用 GameMode 的 `SpendExperience` 扣除经验；
4. 成功后提升 `HandCardLevels[Index]`；
5. 调用 `RefreshHandCards` 重建卡片并刷新费用；
6. 升级成功后退出升级模式。

返回值含义为：`0` 表示成功，`1` 表示已经最高等级，`-1` 表示索引无效、资源不足或塔类无效。卡片根据结果播放成功或失败动画。

## 7. 手牌刷新

`UTDHandPanel::RefreshAllCards` 清空 RootCanvas 的全部子 Widget，重新执行排序、费用读取、资源加载和布局。因此升级后卡片费用和显示顺序会重新计算。`ATDPlayerController::RefreshHandCards` 通过 GameMode 获取 HandPanel 并调用该函数。

## 8. 手牌与部署的协作

手牌系统不直接生成防御塔，而是把索引交给 PlayerController。部署时 PlayerController 使用相同的 `HandCardIndex`：

1. 读取手牌对应塔类；
2. 使用当前手牌等级读取部署费用；
3. 检查格子和费用；
4. 生成塔；
5. 将当前等级传给塔的 `SetLevelDirectly`。

这样手牌显示、费用扣除和生成塔属性由同一个逻辑索引连接，避免 UI 只显示费用但实际部署使用另一套数据。

## 9. 当前限制与可完善内容

- 卡片资源通过固定路径和塔类名称加载，新增角色时必须同步准备对应资源命名。
- 手牌布局使用固定尺寸 `180` 和间隔 `1`，尚未根据屏幕宽度自适应。
- 当前排序以等级 1 费用为依据，升级后不会按新等级费用重新排序，除非调用刷新时排序逻辑改为读取当前等级。
- 卡片通过 WidgetTree 查找第一个按钮，后续可使用明确的 `BindWidget` 按钮变量提高稳定性。
- 手牌升级主要升级后续部署塔；已生成塔的运行时升级由 `ATDBaseTower::LevelUp` 单独负责。

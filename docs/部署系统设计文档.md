# 部署系统设计文档

## 1. 文档范围

本文与当前 C++ 源码同步，描述实际运行时使用的防御塔部署流程。当前主流程由 `ATDPlayerController`、`ATDGameMode` 和 `UTDGridManager` 协作完成；`ATDDeploymentManager` 与 `ATDDeploymentPreviewActor` 保留为可扩展类，但没有被当前主部署流程直接调用。

## 2. 主要类与职责

| 类 | 当前职责 | 代码位置 |
|---|---|---|
| `ATDPlayerController` | 手牌选择、GhostActor 创建、鼠标格子定位、部署检查、扣费、生成塔 | `Private/Core/TDPlayerController.cpp` |
| `ATDGameMode` | 创建网格管理器、维护费用、提供 `SpendCost` 接口 | `Private/Core/TDGameMode.cpp` |
| `UTDGridManager` | 保存格子数据，执行坐标转换、地形/占用/部署类型检查 | `Private/Grid/TDGridManager.cpp` |
| `ATDGridDataActor` | 关卡中保存网格数据，并导入运行时网格 | `Public/Grid/TDGridDataActor.h` |
| `UTDGridDataAsset` | 保存可复用的列数、行数、单元大小和格子数组 | `Public/Grid/TDGridDataAsset.h` |
| `ATDDeploymentPreviewActor` | 独立的无碰撞预览 Actor，支持位置、格子坐标、颜色状态 | `Private/Deployment/TDDeploymentPreviewActor.cpp` |
| `ATDDeploymentManager` | 预留的费用管理 Actor；当前 `StartCostRegen` 为空 | `Private/Deployment/TDDeploymentManager.cpp` |

## 3. 网格数据与合法性

`FGridCellData` 包含三个字段：

- `bDeployable`：配置层面是否允许部署；
- `TileType`：格子类型，当前包含 `GROUND`、`HIGHLAND`、`BLOCKED`、`START`、`END` 和 `HOLE`；
- `bOccupied`：运行时是否已被防御塔占用。

GameMode 在 `BeginPlay` 中创建 `UTDGridManager`，默认初始化为 10 列、8 行、单格边长 200、原点为世界坐标零点；随后遍历关卡中的 `ATDGridDataActor`，调用 `ApplyToGridManager` 导入关卡配置。

`GridToWorld` 返回格子中心世界坐标。`WorldToGrid` 根据以 `GridOrigin` 为中心的网格范围，将世界坐标转换为列、行并检查边界。`CanDeployAtWithPlacement` 的判断顺序为：

1. 坐标必须在网格范围内；
2. 格子必须 `bDeployable` 且未占用；
3. `HOLE` 和 `BLOCKED` 永远不能部署；
4. `GROUND` 只接受 `GROUND_ONLY` 或 `ANY`；
5. `HIGHLAND` 只接受 `HIGHLAND_ONLY` 或 `ANY`。

## 4. 实际部署流程

### 4.1 开始部署

UMG 手牌调用 `ATDPlayerController::BeginPlacement(int32 Index)`：

1. 先调用 `CancelPlacement`，清理上一次残留状态；
2. 根据 `Index` 从 `ATDGameMode::LevelHandCards` 获取防御塔类；
3. 读取塔类默认对象，创建一个临时 `AActor` 作为 `GhostActor`；
4. 创建无碰撞的 `UStaticMeshComponent`，复制塔默认对象的静态网格；
5. 设置 `bDragging = true`，并立即更新 Ghost 位置。

当前主流程使用 Controller 动态创建 GhostActor，而不是直接生成 `ATDDeploymentPreviewActor`。后者提供了独立的绿/红材质预览能力，可在后续重构时接入。

### 4.2 鼠标与格子定位

`GetMouseGridPosition` 通过 LocalPlayer 的 Viewport 获取鼠标屏幕坐标，再调用 `DeprojectScreenPositionToWorld` 得到世界射线。优先使用 `TDGridChannels::DeploymentPlane` 射线命中部署平面；未命中时，以 `Z=0` 的水平面作为回退平面。最后调用 `GridManager->WorldToGrid` 得到列、行。

`UpdateGhostToMouse` 读取格子类型：高台预览高度为 `Z=110`，其他格子预览高度为 `Z=0`；GhostActor 的 XY 使用 `GridToWorld` 返回的格子中心。定位成功后保存 `DragCol` 和 `DragRow`，定位失败则隐藏 GhostActor。

### 4.3 松开手牌与生成防御塔

`EndPlacement` 在拖拽状态下结束拖拽。如果当前格子有效，则设置 `PendingDeployCountdown=5`；Controller Tick 每帧递减计数，归零后调用 `DeployAtCell`。这种短倒计时给 UI 和鼠标释放事件留出稳定时间。

`DeployAtCell` 的实际顺序如下：

1. 检查 GameMode、GridManager 和待部署塔类是否有效；
2. 读取当前手牌等级对应的部署费用；
3. 调用 `CanDeployAtWithPlacement` 检查格子和部署类型；
4. 调用 `ATDGameMode::SpendCost` 扣除费用；
5. 以格子中心和地面/高台高度计算生成位置；
6. 调用 `TryOccupy` 标记格子占用；
7. `SpawnActor<ATDBaseTower>` 生成防御塔；
8. 写入塔的 `GridCol`、`GridRow`；
9. 如果手牌等级高于 1，调用 `SetLevelDirectly` 同步塔属性；
10. 调用 `CancelPlacement` 销毁 GhostActor 并清空待部署状态。

任一步检查失败都会调用 `CancelPlacement`，不会生成塔。费用扣除成功后才生成塔；当前代码在扣费后通过 `TryOccupy` 继续标记格子，建议后续将占用结果也作为生成前的最终保护条件。

## 5. 费用管理

实际运行时费用由 `ATDGameMode` 管理：初始值为 0，上限默认 99，`RegenerateCost` 通过 1 秒循环定时器增加 `CostRegenRate`，并调用 HUD 更新。`SpendCost` 只有在余额不小于所需费用时才扣除并返回 `true`。

`ATDDeploymentManager` 中虽然存在 `CurrentCost`、`MaxCost`、`CostRegenInterval` 和 `CostRegenAmount` 字段，但 `StartCostRegen()` 当前为空实现，未参与实际费用恢复。因此不能把它描述为已接入的运行时费用模块。

## 6. 碰撞通道与备用接口

`TDGridChannels::DeploymentPlane` 和 `TDGridChannels::MapMesh` 分别代表部署平面和地形检测通道。`UTDGridManager::GetDeployLocation` 保留了双射线接口：第一条射线通过部署平面确定格子，第二条射线从格子中心向下检测地形高度；当前主流程使用 `ATDPlayerController::GetMouseGridPosition` 和固定的地面/高台高度，没有调用该备用接口。

## 7. 边界与后续改进

- 统一主流程和 `GetDeployLocation` 的坐标原点语义，避免多个入口的网格换算规则不一致。
- 将 `ATDDeploymentPreviewActor` 接入 Controller，复用其颜色状态和预览材质逻辑。
- 补齐 `ATDDeploymentManager::StartCostRegen`，或删除重复费用接口，避免出现两个费用管理来源。
- 将 `TryOccupy` 的返回值纳入 `DeployAtCell` 的最终成功条件，并在生成失败时释放格子。
